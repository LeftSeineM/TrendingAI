01OpenAI · 2026-08-18

ChatGPT 广告今天进入欧洲，聊天开始成为购买入口

OpenAI 从今天起把 ChatGPT 广告扩展到德国、法国、西班牙等三十一个欧洲市场。广告只出现在免费版和 Go 方案，Plus、Pro 与 Enterprise 保持无广告。真正的变化不在多了一块商业位，而在投放场景：用户会在聊天里交代预算、偏好和限制，再让系统协助比较产品、安排行程或选择软件。这比搜索关键词更接近决定发生的时刻，也让聊天框成为新的消费入口。

OpenAI 表示广告会清楚标注、与回答分开，广告主也看不到用户对话；这些是平台承诺，不等于用户可以停止判断。只要商业系统开始围绕转化率优化，最需要观察的就是推荐、回答与广告在视觉和心理上是否仍然容易区分。实际使用时，可以把赞助内容当作发现线索，但价格、适用条件和替代选项仍应另行核对，尤其不要把“出现在回答旁边”误认为模型替它背书。

02OpenAI · 2026-08-19

企业想让 AI 看懂连续任务，又不留下原始对话

OpenAI 宣布继续向符合条件的 API 客户提供零数据留存：请求处理完后不保留提示词和模型回复，企业内容默认也不用于训练。难题在于，代理型任务往往跨越多轮交互，风险可能只有把若干步骤连起来才看得见；逐条检查既看不全，又不能为了安全把敏感原文长期交给平台。为此，公司预告了 Private Safety Processing，希望只返回有限的风险信号，同时不让 OpenAI 人员接触底层内容。

这不是所有 ChatGPT 用户已经自动获得的新隐私开关，也不是一套完成部署的通用方案。官方写明它正在与早期客户测试；零留存场景中的内容仍放在客户控制的基础设施，另一种由客户掌握密钥的托管方式还在开发。对准备把合同、病历或内部研究交给模型的团队，眼下最实际的动作仍是确认合同资格、数据落点、密钥控制和日志策略，而不是看到“零留存”四个字就默认整条工作流都没有副本。

03AID-Guard 论文 · 2026-08-21

一次批准为什么可能让代理发出两封邮件

一篇新论文把代理安全从“是否允许调用工具”推进到“批准最终产生了什么结果”。例如用户同意从指定账户向指定收件人发一封报销邮件，代理可能在真正提交前替换附件；也可能邮件已经发出，只是服务端响应丢失，于是系统重试并发送第二封。研究者提出的 AID-Guard 会在提交时重新核对请求与服务状态，结果不明时保留原授权，只有确认没有产生效果后才允许释放或生成一次继任操作。

这个思路比不停提醒模型“要谨慎”更接近工程问题，因为它把一次用户决定绑定到一次外部效果。论文的 Python 与 SQLite 原型在限定的 Stripe、Resend 和 MCP 测试中没有产生重复或未授权效果，但严格策略也明显降低了正常任务完成率；它还不是可直接部署的行业标准。对今天正在搭代理的人，启示很具体：付款、发信、建账号等操作必须有幂等键、提交前复核、可审计状态和明确的失败恢复规则，不能把模型的一句“已完成”当作交易事实。

Google Blog · 2026-08-12

连接 Gemini 之前，先缩小它能碰到的账户范围

Google 正在分批为 Gemini 增加 Granola、Otter.ai、Wix、Ticketmaster、OpenTable 等连接，覆盖会议摘要、网站编辑、餐厅和活动预订。官方表述是“未来几周陆续推出”，因此不同地区和账户未必已经可用。轮到你的账户开放时，不要一次接通所有服务：先选一个低风险场景，检查授权页允许读取什么、能否直接写入或下单，并把最终付款与公开发布留给人工确认。若服务支持单独的工作账户或测试站点，优先用隔离账户试跑；真正省心的连接，应当也容易撤销和追踪。

值得多想一步

OpenAI · 2026-08-18

更强模型的真实成本，开始包含减速和隔离

OpenAI 表示，在一起与 Hugging Face 有关的事件以及内部模型 Astra 可能触及关键网络能力门槛后，公司暂停了可执行代码或访问互联网的前沿模型推理，并对拟部署模型的强化学习训练进行了两周暂停；规模最大的前沿强化学习计划仍未恢复。这里需要分清：Astra 是尚未发布的模型，关键能力判断来自公司内部初步证据，外界无法独立复现。

这件事仍然改变了“发布越快越好”的成本计算。隔离不可信代码、限制网络访问、监控中间行为和逐项恢复工作负载都会消耗时间与算力，但如果模型能自行发现并利用系统漏洞，减速本身就是产品工程的一部分。以后看模型路线图，除了性能和价格，还应追问它在什么环境里测试、哪些工具权限被关闭，以及谁有权在证据不足时按下暂停键。
