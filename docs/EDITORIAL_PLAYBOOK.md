# TrendingAI 主编手册

这份日报不是热门链接榜，也不是模型发布记录。它要替读者完成一次真正的编辑工作：从当天噪声里找出少数重要变化，核对事实，解释与日常学习、工作、创作和消费的关系，并留下可继续思考的问题。

## 1. 成品标准

每天成功投递至多一份；从北京时间 08:00 起按现有每小时检查补齐当天任务，不把设备离线视为失败。默认 8 条，允许 6～12 条，读完约 6～10 分钟。读者即使不打开原文，也应该知道：

- 发生了什么，当前究竟已经可用、正在测试、只是研究成果，还是尚未兑现的计划；
- 为什么这件事现在重要，它改变了谁的什么行为；
- 对真实生活或工作有什么可尝试的用法，也有什么限制、成本或风险；
- 哪些说法来自事实，哪些是主编基于事实作出的判断。

正文必须像自然中文文章。段落数量、叙述顺序可以随内容变化，不要把每条稿件写成相同的“发生了什么—为什么重要—怎么用”填空题。

## 2. 研究流程

1. 先确定时间窗。新闻候选覆盖过去 24～48 小时；研究前言允许梳理近 7 天的持续主题，论文优先近 7 天首次发布或有实质修订的原文，明确标注原始日期和版本。较旧论文只作背景，不冒充新论文、不为补配额单列。已经写过且没有实质进展的消息不重复收录。
2. 广泛浏览后再选题。优先查看产品发布说明、官方博客、论文、代码仓库、监管文件、作者原文；可靠媒体用于补充背景和外部质疑。
3. 重大主张至少用两个相互独立的来源交叉核对。无法核对的数字、效果和发布日期不写成确定事实。
4. 阅读原文而不是只读搜索摘要。记录实际可用范围、地区、价格、资格、数据来源、实验条件和作者明确写出的局限。
5. 选题不按热度排序。只有能回答“它改变了什么”或“读者能据此做什么”的内容才进入正文。
6. 为整期找一条隐约的主线，但不要强行把无关新闻拼成宏大趋势。主线写进导语和主编手记，不必给每条新闻下同一种结论。

推荐的信源优先级：官方或第一手材料 > 研究原文 > 有编辑审核的专业媒体 > 作者公开解释。社交平台热度、排行榜名次、点赞数和跑分只能作为线索或旁证，不能成为选题价值本身。

## 3. 编排方式

- `lead`：恰好三条本期主稿。每条 150～520 个汉字，可以写 1～3 段。
- `use`：至少一条今天或近期能尝试的工具、方法或工作流。需要说明适用对象和使用边界。
- `think`：至少一条需要多想一步的产业、研究、治理或文化问题。判断要落在具体事实上。
- `quick`：至少一条短讯，只保留最重要的事实和意义，不把短讯硬拉成长文。

整期至少来自四个不同域名，至少两条直接使用官方、第一手或研究原文。三条主稿不能只是同一家公司的一组公告。

### 3.1 配比与阅读顺序（2026-09-22 起新稿）

默认 8 条正文：5 条应用实践（62.5%）、1 条其他能力进展（12.5%）、2 条论文解读（25%，AI 与具身各一条优先）。这是针对本刊读者的编辑安排，不是研究证明的唯一最佳比例。应用始终为主，按正文独立条目计数，保持 55%～65% 且不少于 4 条；论文属于能力层，不重复计数。可用 7 条的 4 应用 + 3 能力组合；优质论文不足时保留 1 条，不拿摘要凑两条。每期至少 1 条论文，选题持续覆盖 AI 与具身两类，避免长期偏科。

标题 → 每日一句 → Codex 额度刷新消息置信度一行 → 研究前言 → 完整目录（栏目名、全部文章子标题及一句阅读提示）→ 正文 → 主编手记。引语、额度行、前言和目录均不计入应用/能力条数。

- 前言使用 `standfirst`（建议 180～260 汉字）和独立小标题 `research_title`，讲一个最近研究问题：为什么此时讨论、关键方法改变了什么、证据能支持到哪、与本期实践的关系。不要重复目录，不按热度复述发布；Jev 只是可选例子，不固定每天写。前言附 1～3 条一手来源。
- `lead` 仍恰好 3 条，其中至少 2 条应用/能力落地；论文通常放 `think`，也可把特别重要的一条放 `lead`。`use`、`think`、`quick` 均至少 1 条。每条独立标记 `track` 为 `application` 或 `capability`，按主要价值归类，不能把框架公告硬算应用。
- 应用至少 2 条给个人、学生或小团队当天 15～30 分钟可完成的第一步，写清前置安装/下载不计入练习时间、账号、设备、预算、国内入口、隐私与人工验收；不可直接试用的企业观察案例不超过应用的一半。至少 1 条真实团队工作流。
- 每天审阅至少 12 个近 24～48 小时候选，其中至少 4～6 个国内一手候选，覆盖至少两类；质量足够时保留至少 2 条国内实践/学习资源，优先一条国内可复现小项目。不得用旧闻和软文补配额。

### 3.2 Codex 额度消息：置信度不是预测概率

只判断网上“额度重置、临时加量、活动补偿”等消息的证据强度，不查询或刊登主编个人账户余额，不预测所有人的刷新时间，不自动兑换重置券。固定标注“Codex 额度刷新消息置信度”，摘要必须说清所评估的具体消息或“未发现可核实的新公告”，并附当天带时区的核验时间和 1～3 个可点击来源。移动端可自然换行。

每日联网查看官方定价/使用说明、官方更新或公告。入口：<https://learn.chatgpt.com/docs/pricing>、<https://developers.openai.com/codex/changelog>；服务故障核对 <https://status.openai.com/>。搜索结果日期不能当作消息发布日期。社区原帖/第三方网站只能作线索和旁证，先追到原始出处；同源转载不算独立证据。普通账户的正常滚动刷新、全体/部分用户临时加量、故障恢复和付费额度必须区分。

辅助检索入口：<https://whennextreset.com/>（逐条公告与方法说明）、<https://codexreset.org/>（时间线与预测）、<https://codexreset.app/>（另一套预测）。这些均不是官方保证；每天核对采集截止时间、事件类型、原帖和历史是否缺失。When Next Reset 的方法页明确使用单一上游合集，不能把它和同源镜像算两份独立验证。不同网站给出不同概率时不取平均、不择高引用；本刊置信度根据原始证据评定。若原帖无法访问，只能注明“第三方转述，原帖未核实”；“承诺将重置”与“已经到账”必须分别判定，网站推算的具体时刻不得冒充官方时刻。

- 高：官方原始公告明确确认该消息，且适用套餐、地区、时间窗与当前结论匹配；只能对明确支持的命题评高，不能把正常额度规则当成全员加量的证据。
- 中：至少两个独立、有时间与适用范围的可核验一手报告，但没有官方确认；写清“部分用户报告”，不外推全体。
- 低：仅单个可核验报告，或证据陈旧、范围不清、有矛盾；必须说明缺口。
- 未核实：没有可验证的新消息、原文不可访问或无法判定。写“暂无可核实的统一重置／加量公告；以账户用量页为准”，不把没有证据写成“不会刷新”。检索失败应写“本次检索未完成”，不得声称全网没有公告。

不输出 80%/95% 等无校准依据的概率，不把官方故障状态正常解释为额度已刷新，不给账户、付款或验证码交给第三方网站，不引用匿名截图作为确认。

### 3.3 AI／具身论文解读

阅读论文正文的方法、实验和局限部分及补充材料中相关段落，不只读摘要。来源用论文原文（arXiv、会议/期刊或作者实验室），标注首发/修订日期、预印本或录用状态，有代码/权重时核对实际可用和许可。

每条以自然段回答：研究解决什么具体瓶颈；方法相对既有做法改变哪一步；最有解释力的结果及样本/基线/评测条件；至少一个局限或失败模式；读者能借鉴或复现什么、需要何种算力与技能。没有跑过不得声称复现成功。

具身论文额外交代机器人本体、传感器、训练/测试任务和环境、真实机器人还是仿真、跨物体/场景泛化、成功率分母/重复次数（若原文未给则明确缺失）、部署延迟与安全接管。仿真成功不能当成现实稳定可用，剪辑演示不能代替系统实验。不得把硬件昂贵的实验写成普通人半小时可复现；可以给无硬件的论文图表核查/公开轨迹分析任务。

## 4. 写作纪律

- 每期在标题之后、导语之前放一条“每日一句”。必须能追溯到可靠原文，保留作者、来源名称和 `https` 来源链接；找不到可信出处就换一句，严禁使用网络流传但无法核实、被断章取义或错误署名的“名人名言”。中文可自然翻译，但不得改变原意。引语应与当天主线形成轻微呼应，不要为了贴题硬改原话，也不要写成鸡汤。
- 邮件主题 `subject` 和页面主标题 `title` 都必须以当天日期开头，格式固定为 `YYYY年M月D日｜`，例如 `2026年8月25日｜AI 开始改变软件的购买方式`。日期之后才写真正有信息量的判断。
- 标题写变化和冲突，不照抄英文标题，不使用“重磅”“炸裂”“遥遥领先”。
- 导语不是目录，要给出今天的整体判断，同时保留不确定性。
- 跑分、参数和融资金额只有在能支持判断时才出现，不能作为开头和结论。
- 明确区分“能演示”和“能稳定使用”、“论文结果”和“消费产品能力”、“公司宣称”和“第三方验证”。
- 不编造个人体验，不假装已经使用尚未实际测试的产品。
- 不写“值得持续关注”“行业将迎来变革”“未来可期”“具有重要意义”“普通用户会逐步感受到变化”等万能句。
- 素材不足就缩短或舍弃；没有可靠主编稿，就不发送。
- 每条稿件只放一个最能支持正文的原始来源链接。正文涉及重大争议时，可在段落内明确写出另一来源的名称，但不要堆链接。

## 5. 稿件文件

每天的文件保存为 `data/editorial/YYYY-MM-DD-morning.json`。这里的 `morning` 是为了兼容既有发送锁的内部标识，对读者展示为“每日版”。结构如下：

```json
{
  "date": "2026-08-24",
  "edition": "morning",
  "subject": "2026年8月24日｜一句真正有信息量的中文判断",
  "title": "2026年8月24日｜网页和邮件里的主标题",
  "daily_quote": {
    "text": "一句经可靠原文核实、与当天主线轻微呼应的引语。",
    "author": "作者姓名",
    "source_name": "原始演讲、著作或可靠档案名称",
    "source_url": "https://可核验出处"
  },
  "standfirst": "70～260 个汉字的导语，说明今天的主线、变化和边界。",
  "editor_note": "45～220 个汉字的主编手记，提出一个基于本期事实的观察或问题。",
  "stories": [
    {
      "section": "lead",
      "title": "自然中文标题",
      "teaser": "20～90 个汉字的阅读路线提示，不重复标题。",
      "source": {
        "name": "来源名称",
        "url": "https://原始来源链接",
        "type": "official",
        "published_at": "2026-08-24T01:00:00+08:00"
      },
      "body": ["第一段。", "第二段可选。"],
      "tags": ["产品", "工作流"]
    }
  ]
}
```

`daily_quote.text` 为 8～140 个字符；作者、来源名称和来源链接均为必填。`source.type` 只能是 `official`、`primary`、`research`、`media`、`author`。不要增加脚本不认识的字段来替代正文。

新稿设置 `format_version: 2`，在上述结构上增加以下字段；历史已存在的有效稿不改写。下面只是结构示意，核验时间和结论必须由当期真实研究填入：

```json
{
  "format_version": 2,
  "codex_quota_watch": {
    "confidence": "未核实",
    "summary": "暂无可核实的统一重置／加量公告；以账户用量页为准。",
    "checked_at": "2026-09-22T20:00:00+08:00",
    "sources": [{"name": "官方用量说明", "url": "https://learn.chatgpt.com/docs/pricing"}]
  },
  "research_title": "结构化输出与正确决策仍是两回事",
  "research_sources": [{"name": "研究作者原文", "url": "https://typesafe.ai/blog/introducing-system-one-models-and-jev"}]
}
```

每条 `stories` 加 `track`；论文条目另加 `paper_topic: "ai"` 或 `"embodied"`，`source.type` 必须为 `research`，`track` 必须为 `capability`。非论文条目不写 `paper_topic`。目录由栏目、`title`、`teaser` 自动生成，邮件链接到网页对应文章，网页目录跳转页内锚点。不要手写另一份容易失配的目录。

## 6. 发布前自检

```bash
python scripts/publish_editorial_issue.py --edition morning --validate-only
python scripts/publish_editorial_issue.py --edition morning --dry-run
```

校验还需人工核对额度行位置及来源、研究前言、完整目录/链接、论文实验边界、应用占比和国内可执行建议；通过脚本不等于事实已验证。

定时主编任务依照保存的双重防重流程研究、验证，常规发布只提交当天 JSON；确认 main 成功标记缺失且主/兜底工作流均无活动运行后，才可触发一次既有发送工作流并核验结果。已发送则静默退出；失败当天不补触发。缺稿/校验失败不得生成模板替代内容。必要维护按下述持续授权执行，不能把修复排版当成跳过主编质量或防重检查的理由。
